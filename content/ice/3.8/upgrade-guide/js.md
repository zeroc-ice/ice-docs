### NPM Package

The Ice NPM package has been renamed and converted into a scoped package: `@zeroc/ice`. This new package also includes
the `slice2js` compiler for Linux, macOS, and Windows.

### Upgrade Steps

1. Uninstall the old packages:

   ```shell
   npm uninstall ice slice2js
   ```

2. Install the new package:

   ```shell
   npm install @zeroc/ice --save
   ```

{% callout type="note" %}

The `slice2js` compiler can be executed by running `npx slice2js`.

{% /callout %}

## ES Modules

In Ice 3.7, you loaded Ice and your generated code with `require` in Node.js, or with `<script>` elements that loaded
`node_modules/ice/lib/Ice.js` and your generated files in a browser, and you selected the module format of the generated
code with the `js:es6-module` or `js:cjs-module` file metadata.

In Ice 3.8, `@zeroc/ice` and the code generated by `slice2js` are ES modules, for Node.js and browsers alike. Replace
each `require` call with an `import` statement:

```diff
-const Ice = require("ice").Ice;
-const Demo = require("./generated/Hello").Demo;
+import { Ice } from "@zeroc/ice";
+import { Demo } from "./generated/Hello.js";
```

A TypeScript application that imported `Ice` from `"ice"` now imports it from `"@zeroc/ice"`.

A web application uses the same `import` statements as a Node.js application, and a JavaScript bundler resolves the
`@zeroc/ice` package; see [Bundling](#bundling).

Remove the `js:es6-module` and `js:cjs-module` file metadata from your Slice files, then recompile them with the
`slice2js` compiler of Ice 3.8.

## Mapping for Slice long

In Ice 3.7, Slice `long` mapped to the `Ice.Long` class. In Ice 3.8, it maps to the JavaScript `bigint` type, and the
`Ice.Long` class has been removed. For a `long` parameter, your application can pass a `number` or a `bigint`.

```diff
-const size = new Ice.Long(0, 1024);
-const next = size.toNumber() + 1;
+const size = 1024n;
+const next = size + 1n;
```

A Slice dictionary with a `long` key now maps to the built-in `Map` type instead of `Ice.HashMap`. In TypeScript,
`dictionary<long, string>` maps to `Map<bigint, string>`. The keys of this map are `bigint` values: `map.get(1n)` finds
an entry that `map.get(1)` does not. A dictionary with a struct key still maps to `Ice.HashMap`.

## Null Structs and Enumerators

In Ice 3.7, you could leave a non-optional struct or enumeration set to `null`: Ice marshaled a default-initialized
struct, or the first enumerator of the enumeration, in its place. Ice 3.8 requires a value for every non-optional struct
and enumeration, including sequence elements and dictionary keys and values.

## Bundling

In Ice 3.7, you bundled your generated code with the Gulp Ice Builder, driven by the `js:module` file metadata
directive. Ice 3.8 has no bundler of its own: bundle your application, the `@zeroc/ice` package and your generated code
with a standard JavaScript bundler such as Vite, Rollup, webpack or esbuild. The `js:module` directive remains, and
controls how other generated code imports your generated code, as described in
[Slice Metadata Directives](../slice/slice-metadata-directives).

The optional `@zeroc/slice2js` package provides a plug-in for these bundlers that compiles your Slice files as a step of
your build. Install it as a development dependency:

```shell
npm install --save-dev @zeroc/slice2js
```

and add the plug-in to the configuration of your bundler; see the
[@zeroc/slice2js README](https://www.npmjs.com/package/@zeroc/slice2js) for the plug-in options.

## Node.js and Browsers

The `@zeroc/ice` package requires Node.js 22.16.0 or later. Ice supports the WebSocket transport with Node.js 24 or
later. Support for Internet Explorer has been removed.
