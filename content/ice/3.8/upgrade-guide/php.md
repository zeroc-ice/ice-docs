## PHP Requirements

Ice for PHP 3.8 requires PHP 8.0 or later and runs on Linux and macOS. Ice for PHP 3.7 also supported PHP 5, PHP 7 and
Windows. See [Supported Platforms for Ice 3.8.3](../release-notes/supported-platforms-for-ice-3-8-3) for the tested PHP
versions and operating systems.

## Flattened Mapping

Ice 3.7 provided two PHP mappings: the namespace mapping, and the deprecated flattened mapping that you selected by
compiling your Slice files with `slice2php --no-namespace` (or `-n`) and loading an Ice extension built with
`USE_NAMESPACES=no`. Ice 3.8 provides only the namespace mapping.

To upgrade an application that uses the flattened mapping:

- Remove the `--no-namespace` and `-n` options from your `slice2php` commands, then recompile your Slice files.
- Replace each flattened name with its namespaced name. The flattened mapping joined the Slice module names and the type
  name with underscores, such as `VisitorCenter_GreeterPrxHelper`; the namespace mapping maps each Slice module to a PHP
  namespace, such as `VisitorCenter\GreeterPrxHelper`. The same rule applies to the functions and classes of the Ice
  runtime: `Ice_initialize` becomes `Ice\initialize`, and `Ice_InitializationData` becomes `Ice\InitializationData`.
- Replace the `Ice_Unset` constant, which marks an optional value as not set, with `Ice\None`.

```diff
-$communicator = Ice_initialize($argv);
-$greeter = VisitorCenter_GreeterPrxHelper::uncheckedCast($proxy);
+$communicator = Ice\initialize($argv);
+$greeter = VisitorCenter\GreeterPrxHelper::uncheckedCast($proxy);
```

## Null Structs

When you passed `null` where an operation expects a Slice struct, Ice 3.7 marshaled an instance of the struct created
with its default constructor. Ice 3.8 throws `InvalidArgumentException` from the proxy invocation. The same rule applies
to a struct nested in another struct, a class, a sequence or a dictionary.

Pass an instance of the struct:

```diff
-$greeter->setLocation(null);
+$greeter->setLocation(new VisitorCenter\Location);
```

## Marshaling Hooks and Value Factories

Ice 3.7 called the `ice_preMarshal` method of a class instance before marshaling it, and the `ice_postUnmarshal` method
after unmarshaling it, when the instance's class defined these methods. Ice 3.8 calls neither method.

Ice for PHP 3.8 also has no value factory and no custom Slice loader: when it unmarshals a Slice class, it creates an
instance of the class generated by `slice2php`.

To upgrade:

- Move the code of `ice_preMarshal` to the code that sends the instance, before the proxy invocation.
- Move the code of `ice_postUnmarshal` to the code that receives the instance, after the proxy invocation returns.
- Remove your value factories and the calls that register them with `getValueFactoryManager`.

## ice.hide_profiles

Ice for PHP 3.8 has no `ice.hide_profiles` directive; remove it from your PHP configuration. In Ice 3.7, this directive
was enabled by default and overwrote the value of `ice.profiles` after the Ice extension read it, to hide the profile
file location from the scripts running in the same web server.

To avoid sharing PHP settings between applications, run each application in its own PHP-FPM pool. See
[Profiles in PHP](../runtime/communicator/communicators-in-php#profiles-in-php).
