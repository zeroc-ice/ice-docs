title: Terminology
---

Ice uses the terminology of other RPC frameworks where it can. This page defines the terms the rest of the manual uses,
and links to the pages that describe each concept.

## Clients and Servers

_Client_ and _server_ are roles that parts of an application take for the duration of a request: the client issues the
request, and the server processes it. An application often takes both roles, for example when a client passes a callback
object to a server, which then calls back into the client.

## Ice Objects

An _Ice object_ is an entity, in the local process or in a remote process, that responds to client requests. Each Ice
object has a unique [object identity](../../runtime/object-identity) and a type, a Slice
[interface](../../slice/interfaces) that defines the _operations_ clients invoke. Besides its main interface, an Ice
object can provide alternate interfaces, known as [_facets_](../../runtime/facets).

## Proxies

A _proxy_ is the client's representative of an Ice object: a local value that holds the object's identity, an optional
facet name, and the information the Ice runtime needs to reach the object. A client invokes operations on an Ice object
through a proxy. A _direct proxy_ holds the [endpoints](#endpoints) of the object; an _indirect proxy_ holds an adapter
ID or only the identity, which the Ice runtime resolves into endpoints with a [locator](#locators).

## Invocation and Dispatch

An [_invocation_](../../runtime/invocation) is the client-side process of calling an operation through a proxy, from
creating the request to returning the response to the caller. A [_dispatch_](../../runtime/dispatch) is the server-side
processing of a request, from accepting the request to returning its response.

## Stringified Proxies

A _stringified proxy_ is the string form of a proxy, such as `SimplePrinter:tcp -p 10000`. See
[Syntax for Stringified Proxies](../../runtime/invocation/syntax-for-stringified-proxies).

## Endpoints

An _endpoint_ is a transport and its parameters, such as `tcp -h server1 -p 10000`: the address at which an object
adapter listens for connections, and the address a proxy holds to reach it. See
[Proxy Endpoints](../../runtime/invocation/proxy-endpoints) and [Endpoint Syntax](../../runtime/endpoint-syntax).

## Communicators

A [_communicator_](../../runtime/communicator) is the main entry point to the Ice runtime. It holds the configuration
[properties](#properties) and opens and caches the outgoing connections that proxies
use{% iflang langs="cpp,csharp,java,js,python,swift" %}; it also creates object adapters{% /iflang %}.

## Connections

A _connection_ links two peers over a transport. See [Connection Management](../../runtime/connection-management).

## Transports

A [_transport_](../../runtime/transports), such as `tcp`, `ssl`, `ws`, `wss` or `udp`, carries the messages of the
[Ice protocol](../../protocol) between two peers.

## Object Adapters

An [_object adapter_](../../runtime/dispatch) dispatches the requests it receives to the servants you register with it.
A communicator can create several object adapters, each with its own configuration.

## Dispatcher

A [_dispatcher_](../../runtime/dispatch/dispatcher-api) is the programming language abstraction for a
[dispatch](#invocation-and-dispatch): it accepts a request and returns the corresponding response.

## Servants

A _servant_ is an instance of a class that you write in your server to implement one or more Ice objects; the servant is
said to _incarnate_ these objects. Most servants implement a skeleton generated by the Slice compiler, with one method
per operation; a servant can also implement the [dispatcher](#dispatcher) abstraction directly. See
[The Active Servant Map](../../runtime/dispatch/active-servant-map) and
[Default Servants](../../runtime/dispatch/default-servants).

{% iflang langs="cpp,csharp,java,js,swift" %}

## Middleware

A [_middleware_](../../runtime/dispatch/middleware) is a [dispatcher](#dispatcher) that intercepts a request before it
reaches the servant, and the response before the object adapter sends it back. It can also return a response without
passing the request on.

{% /iflang %}

## Locators

A [_locator_](../../runtime/locators) is an Ice object that implements the `Ice::Locator` interface: the Ice runtime
asks it to resolve the adapter ID or the identity of an indirect proxy into endpoints. The
[IceGrid](../../services/icegrid) registry is a locator. A locator lets a server move to another address without
invalidating the indirect proxies that clients hold.

## Routers

A [_router_](../../runtime/invocation/routers) forwards the invocations of the proxies configured with it to their
target objects. [Glacier2](../../services/glacier2) is such a router.

## Asynchronous Method Invocation

With _asynchronous method invocation_ (AMI), the calling thread does not wait for the invocation to complete: depending
on the language mapping, the invocation returns a future or an awaitable, or calls a callback when it completes. See
[Operations](../../slice/operations).

## Synchronous Method Invocation

With _synchronous method invocation_ (SMI), the calling thread waits until the invocation completes. In languages with
async/await support, use AMI even when the mapping also provides SMI.

A server cannot tell whether a client invoked an operation synchronously or asynchronously.

## Asynchronous Method Dispatch

With _asynchronous method dispatch_ (AMD), the implementation of an operation frees the dispatch thread while it waits,
for example at an `await`, and completes the dispatch later. See [Operations](../../slice/operations).

## Synchronous Method Dispatch

With _synchronous method dispatch_ (SMD), the dispatch thread stays busy until the implementation of the operation
returns.

A client cannot tell whether the server dispatched a request synchronously or asynchronously.

## Properties

Much of the Ice runtime is configurable via [_properties_](../../runtime/properties-and-configuration). Properties are
name-value pairs, such as `Ice.Default.Protocol=tcp`. Properties are typically stored in text files and parsed by the
Ice runtime to configure various options, such as the thread pool size, the level of tracing, and various other
configuration parameters.
